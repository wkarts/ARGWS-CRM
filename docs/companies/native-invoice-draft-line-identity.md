# Persisted private line identities and exact issued mapping

474 integration contract (no historical migration edits): after the existing private draft/event/request/invoice schemas, run `NativeCompanyInvoiceDraftLinesSchema::ensure(db,prefix)` and `(new NativeCompanyInvoiceDraftLines(db,prefix))->backfill()`. DDL is separate; backfill is one owned transaction and must succeed before release tracking. All revisions are derived from actual canonical payloads with matching immutable event hash and independent audit receipt. Existing inconsistent identities are rejected, never repaired silently.

Tables: `company_invoice_draft_lines` retains each revision's own IDs, source event, position and canonical line hash; `company_invoice_draft_line_transfers` records the real invoice/itemable IDs and audit receipt. Namespace49 transports a draft-line identity as `invoice_item`, distinct from a plain emitted itemable ID and catalogue item namespace34. No invoice number is reserved to create private lines.

New draft create/change/cancel/issue writers maintain the projection in their existing transaction. Issuance receives the exact IDs returned by the original invoice writer's INSERT operations, through the same-instance transaction-bound creation proof. The complete canonical payload and each line hash must match before mapping. The resulting audited mapping hash is embedded in the immutable issue receipt. Replay verifies that mapping; it never reconstructs it by matching positions or amounts from an existing invoice. Source position only identifies the declared payload entry passed unchanged to the attested writer.

Historical issued drafts without an original insertion proof get verified historical draft-line identities, **not** manufactured transfers. Old receipts remain unchanged. No automatic migration of old custom-field values to a fabricated new line ID is performed. The transfer intentionally does not FK to current itemable: its immutable historical evidence must survive a future authorized line replacement; source line/invoice/audit are FK-bound.

The PHP8.4 SQLite tests run actual source services, rollback/replay/corruption and metadata failure cases. MySQL schema/locking and matrix8.1/8.5 remain pending. Editor custom-field handoff across revisions and the draft preview wiring are subsequent integration work, not claimed by this storage contract alone.

The issuance compositor now transfers authorized current draft-line custom fields through the exact writer's creation proof. It binds a real persisted source-to-target mapping, validates native definitions, records a source/target/value-hash audit receipt, and confirms field storage. A create-only actor receives no general edit permission. A failed target field insert rolls back invoice allocation, draft state, transfer mapping and metadata together. Issue replay does not reapply fields or overwrite later authorized metadata. Explicit editor handling of field values when moving to a new draft revision remains separate; old revision identities are never accepted as current IDs.
