# Native invoice file identity

The native `files.id` is allocated in the same owned transaction as the private financial blob and the `company_invoice_file_projection` receipt. The receipt is authoritative for issuer, invoice and private file key. Browser filenames, filesystem paths and keys never grant access.

Migration 474 must first ensure `NativeCompanyInvoiceFileSchema`, then call `NativeCompanyInvoiceFileBackfill::run` outside any pre-existing transaction. Backfill validates invoice/document issuer lineage and the existing content hash, preserves every blob/public key/visibility/active state, and allocates native metadata only. Its whole transaction rolls back on any failed receipt. Replays retain the original native IDs. No GET creates or adopts records, and NULL historical invoices are not adopted.

`NativeCompanyInvoiceFiles::page` supplies native attachment metadata, including real ID, key and revision, to the existing invoice view. `read`/`readKey` return verified bytes after authorization and audit. `nativeMetadata` explicitly strips private content from upload responses. `visibility` updates the native projection and financial portal authority atomically with revision checks.

The Misc upload, external-reference and visibility branches are implemented, but **route admission is not a claim of complete parity**. The invoice preview/download integration is composed by its owner. Outstanding contracts: primary NULL historical uploads, other sales document types, origin-bound attachment email delivery and original historical filesystem lineage. Native uploads now use the exact issuer allowed_files configuration, the lower PHP upload/post limit and a hard 20 MiB cap. The previous CompanyInvoiceAttachments upload API retains its 2 MiB PDF/image contract for existing callers. Migration 474 must call CompanyInvoiceAttachmentSchema::ensureNativeCapacity outside transactions to widen the existing content column from MEDIUMBLOB to LONGBLOB without changing existing bytes; the native writer refuses content above MEDIUMBLOB capacity until that migration is verified. Shared NativeCompanyFileContent decodes/reencodes bounded raster images, validates PDF signatures and inspects ZIP/Office container bounds without extracting; opaque documents are forced downloads, not asserted malware-free. Do not expose unsupported branches through a global fallback.

Verification: real PHP 8.4/SQLite tests exercise existing 137 attachment checks plus owned-boundary, audit-ignore, ID/replay, cross-company, revision, visibility, rollback and migration replay/history invariants. MySQL 8.1/8.5 runtime and browser verification remain pending.

External links have no private blob/file_key; the same receipt has an explicit request key and verifies original provider/name/URL/author before projection. Only HTTPS Drive/Dropbox host allowlists are accepted, no userinfo/port and no server fetch. Download cannot treat an external reference as bytes. Removal retains real files metadata and receipts, but deactivates the source/financial blob in the same transaction.

## Proven primary historical lineage

Native-only writer entrypoints may attach NEW private blobs to an invoice whose persisted issuer is NULL only after NativeCompanyInvoiceIdentity proves the installation primary and staff ACL. The invoice row is never rewritten. Existing callers retain the original named-only contract. The projection stores an explicit source_kind (blob, external, legacy_fs).

Migration projects existing native files for NULL invoices only into the proven primary; it neither renumbers existing files IDs nor moves their bytes. Legacy filesystem reads require the configured invoice root, canonical invoice directory/filename, no symlinks, same opened inode and bounded verified read. Removal revokes the projection and old customer visibility, retaining physical bytes and metadata. Global/public preview routes still require the owning controller's revocation fence before admission; the old file path must not bypass the projection. Portal authorization for NULL invoice blobs is a separate binding path and is not granted by the staff selector.
