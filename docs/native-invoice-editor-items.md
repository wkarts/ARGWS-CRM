# Native invoice editor line identity

The original `admin/invoices/invoice_template.php` and original custom-field renderer remain the markup source. `NativeCompanyInvoiceEditorItems::load` supplies real issued itemable IDs or namespace49 IDs of the exact current persisted draft revision. It never uses catalogue identity or position as an ID. Its private construction binds the database, prefix, issuer, actor and parent; live authorization/revision checks reject stale or cross-context use.

New-row definitions are authorized by invoice creation or the exact parent invoice/draft edit permission, not catalogue items permission. Existing row values pass through the original scoped custom-field reader. No capability is accepted from HTTP. The portal-registration branch of the shared helper remains intact. Legacy calls without the typed projection keep their existing behavior.

`tests/companies/native_invoice_editor_items.php` executes real SQLite ownership and the production field helpers, with a deterministic input/translation rendering seam. It checks draft/issued storage identities, create-only access, forbidden edit/context changes, escaped values and stale revisions. This does **not** claim that the complete editor, remaining tax/recurrence/merge dependencies, HTTP or browser flow are complete; the parent route remains unadmitted until that graph is connected and tested.

The existing applied-row block now obtains taxes from that typed row and calls the actual issuer catalog dropdown with its proven historical taxes. It no longer invokes the legacy item-tax helper or `misc_model` on that branch. The same block escapes descriptions/long descriptions and the unit attribute for named DTOs; the legacy branch is unchanged. `native_invoice_editor_tax_rows.php` evaluates this exact production block with the real catalog service, verifies selected historical taxes, A/B isolation, persisted IDs, forged-row rejection and HTML escaping. It remains a fragment test, not a full page rendering claim.
