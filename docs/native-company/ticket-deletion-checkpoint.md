# Native Tickets: retained deletion receipts (core 474)

The existing `Tickets::delete` and `delete_ticket_reply` routes now have named-company adapters. They require attested context, POST/CSRF, the current ticket revision, a request nonce, and a separate reply revision when applicable. The original principal path remains unchanged. No route admission is added by this patch.

Deletion appends a source-bound tombstone, bumps the parent revision, and writes the durable command receipt and audit in the same issuer transaction. Messages, authors, contact receipts and file bytes are retained. Exact retries validate the original receipt and current authority; a receipt does not allow reading the deleted content. Revoked membership and departments still deny access.
